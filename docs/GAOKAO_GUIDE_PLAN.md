# 高考指南双入口技术方案与实施进度

## 目标

在现有智能问答之外增加“高考指南”产品入口，并让智能问答能够识别高考志愿问题。指南以省内位次为主键，按省份、年份、科类、批次、院校专业组和专业保存数据；所有结果保留来源、抓取时间、文件摘要和口径说明。

## 产品结构

- **智能问答**：保留现有 recipe、dev、chat、naming agent，新增 gaokao agent。高考问题走结构化检索和指南计算，模型只负责解释，不直接编造分数线。
- **高考指南**：表单输入省份、年份、科类/选科、分数或位次、批次、地域和专业偏好，返回冲/稳/保三档院校专业组，并展示历年位次、招生计划变化、选科要求和官方出处。
- 所有高考相关结果固定展示：`数据仅供志愿填报参考，不构成录取承诺；招生政策、计划和录取结果以当年省教育考试院及招生院校官方发布为准，因使用本服务产生的任何后果由用户自行核验和承担。`

## 数据口径

### 必填维度

`province`, `candidate_year`, `reference_year`, `track`, `batch`, `source_id`。`candidate_year` 是考生画像所属年份，`reference_year` 是用于比较的历史投档年份。`track` 使用省级官方口径，例如 `物理类`、`历史类`、`理科`、`文科`、`综合`，禁止跨口径比较。

### 数据表

- `gaokao_sources`：来源机构、URL、文件摘要、抓取时间、发布版本、授权备注、行数和校验状态。
- `gaokao_cutoffs`：省控线/批次线/特控线，包含分数和官方说明。
- `gaokao_score_bands`：一分一段表，保存分数、累计人数和位次区间。
- `gaokao_admissions`：院校专业组或专业的最低/平均/最高分、对应位次、招生计划和选科要求。
- `gaokao_plans`：当年分省分专业招生计划，用于修正历史位次波动。

### 来源优先级

1. 教育部阳光高考和各省教育考试院；
2. 招生院校本科招生网公布的分省分专业录取数据和招生章程；
3. 省级招办授权的志愿辅助系统；
4. 其他来源只能作为待核验线索，不能进入已发布结果。

每个导入文件必须带来源 URL、发布机构、年份、口径、SHA-256 和解析行数；来源缺失、重复主键、跨省份/科类混入或校验不通过时拒绝导入。

## 位次估算

1. 用户给出分数且未提供位次时，先在同省 `candidate_year`、同科类的一分一段表中反查累计位次。
2. 用户直接给出位次时，不用跨省换算，不把原始分数作为跨年度主键。
3. 院校投档线按 `reference_year` 查询，比较候选人的位次与该年度最低位次；候选人年份和投档线年份可以不同。
4. 使用对比年度的招生计划和专业组口径计算可解释的冲/稳/保；缺少同口径录取数据时标记“数据不足”，不输出伪精确概率。
5. 结果同时展示对比年度、最低位次和位次差值，推荐只是统计估算，不替代正式志愿填报。

## 导入流程

```text
官方 CSV/XLSX/JSON/PDF
  -> source manifest + SHA-256
  -> 严格 schema 校验
  -> MySQL staging
  -> 主键/口径/行数/范围校验
  -> 正式表 upsert
  -> 导入审计记录
```

导入脚本支持 `--dry-run`、`--source-url`、`--publisher`、`--year` 和 `--province`，默认拒绝低质量或缺来源文件。正式导入前需人工核对官方文件与解析行数，数据库不接受未核验数据。

## 交付顺序

1. 建模、校验器、导入脚本和指南查询服务；
2. 新增 `/api/v1/gaokao/*` 接口和问答路由；
3. 前端主入口切换为“智能问答 / 高考指南”，指南表单和结果卡片；
4. 导入经过校验的 2026 当前年度数据包；
5. 用官方样例做接口、位次匹配和 UI 回归。

## 发布约束

数据包未完成来源核验前，指南接口返回“数据建设中”或数据不足，不得以模型生成内容替代数据。任何高考回答必须包含免责声明和来源列表。
