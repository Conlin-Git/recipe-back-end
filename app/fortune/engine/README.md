# Recipe 内置紫微斗数引擎

来源：https://github.com/Renhuai123/ziwei-doushu

固定版本：`a600484a49255039d0725f1ba9e11ca81a948f97`。`vendor/ziwei` 是该版本所需排盘、历法、四化、运限、格局与十二神模块的原样副本；许可证见 `vendor/LICENSE.ziwei-doushu`。本站只复用 MIT 排盘代码，不打包上游 Next.js 站点、付费解读、Release 数据集或倪海厦课程引文。第三方依赖的许可证随 `dist/THIRD-PARTY-NOTICES.txt` 发布。

`runner.ts` 将已验证的用户输入转换成引擎时辰索引，统一处理农历、经度校正和晚子时换日。Python 后端只启动本机 Node 子进程，不访问原网站、不启动额外 HTTP 服务。排盘规则固定为全书亮度、农历正月初一换年、闰月前后半分。`details.ts` 只适配原模块的输出，完整保留原始命盘，并生成从 1 虚岁到最后一个大限的连续逐年数据（含 1–80 岁）。界面展示本命 / 大限 / 流年、全部星曜亮度、四化叠层、宫干自化、宫干来源、三方四正与格局条件。

原仓库的 `server-only` 是 Next.js 的客户端导入保护；本项目只在服务端 Node 运行，构建时用本地空模块适配，vendor 源码不修改。文字报告直接按引擎结构化输出编排，格局文字来自原 MIT 模块；未内置商业断语库或 AI 解读接口，逐年排盘数据不等于原站逐岁长篇断语。

应用层另提供 `app/fortune/interpretation.py`：用当前配置的 AI 模型把本地命盘解释为短段落，可通过搜索接口或实时读取上游公开星曜定义补充参考。它不是上游商业 AI 接口，不下载完整数据集，不改变本目录的计算规则；联网和模型失败时仍可使用命盘。

## 随 recipe 发布

`dist/runner.cjs`、来源清单、许可证与源码均纳入 recipe 后端 Python 包。生产环境只需 **Node.js 18+**（建议与 recipe 前端构建统一使用 Node 22）和原来的 Python 依赖；不需要 npm、node_modules、原始克隆目录、额外数据库表或服务端口。Node 不在 PATH 时设置 `FORTUNE_NODE_BINARY` 为其可执行文件绝对路径。

后端发布/重启前运行：

```sh
.venv/bin/python -m app.fortune.check
```

需要更新排盘源码或依赖时，在本目录运行：

```sh
npm ci --ignore-scripts
npm run build
npm test
```

产物可跨 macOS/Linux 发布，包含的都是 JavaScript，不包含构建机的原生 npm 二进制。必须将 `dist` 与修改后的源码、`package-lock.json` 一并提交；发布检查会检测源码和产物是否匹配。每次升级保留来源 commit，并更新回归样例。打包后端 wheel 时排除 node_modules，保留源码和 dist。

白话报告逐段覆盖十二宫、格局条件、童限、全部十二个大限和当前流年；指定大限或年份时只取对应计算数据。正文保留有依据的星曜与宫位并解释含义，命盘依据单独保留。年龄范围为起限年龄加 119 的计算终点，不代表当前年龄或寿命。

解读按批次独立收集结果：单批失败不会丢弃其他章节；返回 partial 时附待补齐章节。成功批次仅在本机服务进程内缓存 30 分钟（最多 256 批），重试复用成功内容，重启清空；不写数据库或磁盘。单次模型等待 60 秒，批次总等待 110 秒。

AI智能解读采用参考案例的七章结构：命宫核心格局、身宫分析、突出格局与组合、重要宫位分析、大运走势、五行局分析、人生总体评价。保留实际星曜与亮度并解释含义，基础信息由排盘数据直接生成；默认保留十二个大限，今年流年列在大运走势末尾。参考案例只决定格式，不复用个人结论。
